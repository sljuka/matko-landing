Course boy
GitHub

Courses that belong to the people who make and take them.

Course boy is a local-first course authoring and sharing app, built for freedom, privacy, and learning together. No cloud account. No central hosting service. Course files live on your device, versioned like real work, and teachers share them directly with students — over a peer-to-peer network, or on paper.

Local first

Course content is made from portable files: localized Markdown for written material, and JSON for structured course data. These files describe a course's sections, lessons, and tests — readable, ordinary formats that are easy to inspect, preserve, and move between devices.

Course boy is a desktop app and mobile app is soon to come.

Built

Open course standard

A course is organized into sections, and each section holds lessons and tests. A lesson is a document a teacher or group of teachers writes for students to use; a test is a set of exercises a student answers and gets graded on.

Nothing about the format is proprietary. Because the package is just files on disk, a course survives the app that made it, and it's the same unit the peer-to-peer and print paths both work from.

Built

Creation experience

Lessons are written in a block-based editor — headings, formatted text, images, video, and audio all live in the same document — and the same document is shown to students in a read-only view, so a lesson looks and behaves the same whether you're writing it or taking it.

Built

Print-friendly

The same lesson and test that render on screen also have a print layout, so paper is a first-class way to take a course — not an afterthought. No device and no network are required to use a printed course; a teacher can author on Course boy and hand out paper without either side needing the app again.

Roadmap

Ownership & control

A course's publishing key doesn't have to belong to one person. The plan is m-of-n multisig control over a course's identity, so an individual teacher can own a course outright, or a school can require several staff members to agree before a new version goes out — without handing control to a platform that could take the course down or lock an owner out of it.

Not built yet. Today, a course's sharing identity is a single keypair derived per-course from a teacher's device; multisig control is the direction this is heading, not a shipped feature.

Built

Peer-to-peer sharing

Courses can be shared in a P2P fashion. Either through a hole-punch network, via pen-drive or handing out prited copies. There is no need for cloud or central servers to support the network. Seedbox like services can be used to kick-start the seeding of new courses but are not required nodes in the network.

A course can also be gated to a set of vetted peers, so only people a teacher has explicitly invited can import it.

Built

Version control

A course is edited as a draft, and a teacher explicitly cuts a version when it's ready to go out. Sharing on the P2P network always points at a specific version, not a moving draft.

Mobile & desktop

Built — Course boy runs today as a desktop app (Electron), with the full authoring and peer-to-peer experience available. Mobile app is also available. Browser is not a good fit because the P2P layer uses UDP sockets which browsers don't expose.

Built

Privacy, security, and identity

Course work stays local, with no cloud account required. Students can use the app without ever setting up a keypair. A teacher only needs a persistent sharing identity when they choose to publish a course over the peer-to-peer network — not to write or print one.

Peer-to-peer work runs in a separate native worker, and sharing is always an explicit choice. A keypair gives a teacher a persistent sharing identity, so it should be protected.
