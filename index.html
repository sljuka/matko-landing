Course boy
GitHub

Courses that belong to the people who make and take them.

Course boy is a local-first course authoring and sharing app, built for freedom, privacy, and learning together. No cloud account. No central hosting service. Course files live on your device, versioned like real work, and teachers share them directly with students — over a peer-to-peer network, or on paper.

Local first

Course content is made from portable files: localized Markdown for written material, and JSON for structured course data. These files describe a course's sections, lessons, and tests — readable, ordinary formats that are easy to inspect, preserve, and move between devices.

Course boy is a desktop app and mobile app is soon to come.

Built

Open course standard

A course is organized into sections, and each section holds lessons and tests. A lesson is a document (markdown) a teacher or group of teachers writes for students to read; a test is a set of various exercise types a student answers and gets graded on.

Nothing about the format is proprietary. Because the package is just files on disk, a course survives the app that made it. Since it's not a binary file it can be easily consumed by other apps or services.

Video, images, and other static assets are packaged inside the course's own folder alongside its lessons and tests — a course never references an asset that lives outside it. That's what makes a course a single, self-contained unit that can be copied, handed off, or shared on the peer network as one thing.

Creation experience

Lessons are written in a block-based editor — headings, formatted text, images, video, audio and other content block types all live in the same document — and the same document is shown to students in a read-only view, so a lesson looks and behaves the same whether you're writing it or taking it.

Built

Print-friendly

The same lesson and test that render on screen also have a print layout, so paper is a first-class way to take a course — not an afterthought. No device and no network are required to use a printed course; a teacher can author on Course boy and hand out paper without either side needing the app again.

Roadmap

Ownership & control

A course's publishing key doesn't have to belong to one person. The plan is m-of-n multisig control over a course's identity, so an individual teacher can own a course outright, or a school can require several staff members to agree before a new version goes out.

Roadmap

An AI co-author for teachers

An agent that reads a lesson's content and suggests exercises to pair with it, and recommends how to structure a new course — how many sections, what exercise types fit the subject — instead of a teacher starting from a blank editor every time.

Exercise suggestions

Reads a lesson and proposes exercises, and drafts, that fit it.

Course structure advice

Recommends how to break a subject into sections, lessons, and tests.

MCP-native

Course authoring exposed as MCP tools, so a teacher can build a course from Claude, or any other MCP client — not only Course boy's own editor.

Roadmap

An AI companion for students

A student can talk with the agent through a plain text interface, or interact with an animated mascot instead — the same agent that helps teachers author courses, offering a hint on a stuck question, a short explanation of why an answer was marked wrong, encouragement to keep going.

The same agent can also help figure out what to learn next — from a stated goal, an existing hobby, or a course already underway.

Goal-based paths

Say "electrical engineering" and get a path through the math, physics, and electronics courses it builds on.

Hobby-based discovery

Mention an interest like 3D printing or composting and get courses that build on it.

Mid-course suggestions

While taking a course, it points to other courses that would fill a gap or go deeper on the topic.

Built

Peer-to-peer sharing

Courses can be shared in a P2P fashion. Either through a hole-punch network, via pen-drive or handing out prited copies. There is no need for cloud or servers to support the network. Blinded seedbox like services can be used to kick-start the seeding of new courses but are not required nodes in the network. As long as you can hand out your course to students, every student that downloads your course becomes a seeder.

A course can also be gated to a set of vetted peers, so only people a teacher has explicitly invited can import it.

Built

Version control

A course is edited as a draft, and a teacher explicitly cuts a version when it's ready to go out. Sharing on the P2P network always points at a specific version, not a moving draft.

Mobile & desktop

Built — Course boy runs today as a desktop app (Electron), with the full authoring and peer-to-peer experience available. Mobile app will also be available. Browser is not a good fit because the P2P layer uses UDP sockets which browsers don't expose.

Built

Easy onboarding for non-technical teachers

Getting started only takes a nickname. A teacher who just wants to write a course, print it, or hand it out on a pen-drive never has to touch a keypair to do it. Students never need one at all.

Setting up a sharing identity is a separate, dedicated onboarding step of its own — it only shows up once a teacher is ready to publish a course over the Pear runtime network, not before. Peer-to-peer work runs in a separate native worker, and sharing is always an explicit choice; the keypair behind it is a teacher's persistent sharing identity, so it should be protected.
